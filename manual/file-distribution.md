# ファイル配信

zip などの圧縮ファイルをこのテンプレート自身でホスティングし、難易度表からダウンロードリンクを張る方法を説明します。単曲や差分パッケージの配布を想定しています。

> このページの制限値は **2026年7月現在** の情報です。最新の値は各公式ドキュメントを参照してください。

## 仕組み

`public/downloads/` に置いたファイルは、Vercel によってそのまま静的配信されます。

- 例: `public/downloads/song.zip` → `https://<あなたのサイト>/downloads/song.zip`
- 静的ファイルの配信はビルド扱いされないため、デプロイ回数やビルド時間を消費しません。
- zip はブラウザが自動的にダウンロードするため、追加の設定は不要です。

## 手順

### 1. ファイルを置く

配布したい zip を `public/downloads/` に置き、コミット・プッシュします。

```bash
cp song.zip public/downloads/
git add public/downloads/song.zip
git commit -m "add song.zip"
git push
```

プッシュ後、Vercel が自動的に再デプロイし、`/downloads/song.zip` で配信されます。

### 2. 表からリンクする

`table.config.json` の `columns` に `badge`（または `link`）カラムを追加し、`url` にファイルへのパスを指定します。カラム定義の詳細は [カラム定義](columns.md) を参照してください。

配信ファイルへのリンクには2つの書き方があります。

**パターンA: データにファイル名を持たせる**

データソース（スプレッドシート等）に列（例: `file`）を用意し、ファイル名を入れます。

| title | file |
|---|---|
| My Song | song.zip |

```json
{ "header": "DL", "type": "badge", "label": "DL", "url": "/downloads/{{file}}", "align": "center" }
```

**パターンB: データにパスを直書きする**

データに完全なパスを入れます（例: `url_diff` 列 = `/downloads/song.zip`）。

```json
{ "header": "Chart", "type": "badge", "label": "DL", "url": "{{url_diff}}", "align": "center" }
```

いずれの場合も、パス（またはファイル名）が空の行では DL ボタンは表示されません。加えて、**`/downloads/` 配下のファイル**へのパスを指す場合は、実ファイルが無い行でも自動的に非表示になります（詳細は下記「/downloads/ 配下の実在チェック」）。

> DL ボタンをクリックすると新しいタブが開きますが、zip はブラウザが自動的にダウンロードを開始します。開いたタブはそのまま閉じて問題ありません。

## /downloads/ 配下の実在チェック（ファイル未配置時の自動非表示）

`badge` / `link` カラムの `url` が **`/downloads/` 配下のファイル**（例: `/downloads/{{no}}.zip`、`/downloads/{{file}}`）を指す場合、**そのファイルが `public/downloads/` に実在する行にだけ**リンク/バッジが表示されます。ファイルが無い行では自動的に非表示になります。

- ミラー配信のように、ファイルの用意がレコード公開より遅れる運用でも、**未配置の行にリンクが出ません**（404 リンクを防げます）。
- ファイルを `public/downloads/` に置いて push（再デプロイ）すれば、その行に自動でリンクが出ます。
- `no` のように全行に値がある項目でURLを組み立てても、実ファイルの有無で表示が制御されます。

**実在チェックの対象は `/downloads/` 配下のファイルアクセスURLに限定**されています。そのため、`/guide` のような**サイト内ページへの相対リンク**を誤って非表示にすることはありません。

| 指定（テンプレート解決後） | 扱い |
|---|---|
| `/downloads/26.zip`、`downloads/26.zip`、`/downloads/2024/26.zip` など（`/downloads/` 配下の拡張子付きファイル。サブディレクトリ可） | **実在チェックの対象**（無ければ非表示）|
| `/downloads/`（ディレクトリ）、`/downloads/guide`（拡張子なし＝ページ） | チェックせず常に表示 |
| `/guide`、`/about` など `/downloads/` 以外の内部パス | チェックせず常に表示 |
| `https://...`（絶対URL）、`//host/...`（プロトコル相対）、`mailto:` など | チェックせず常に表示（外部/非ローカル）|

> 判定はブラウザの `<a href>` と同じ規則で解決したパスに対して行います（先頭スラッシュの有無・`./`・`../` は正規化されます）。実在チェックはビルド / 再検証時の `public/` の状態に基づくため、ファイルを追加・削除したら再デプロイで反映されます。

## ファイル名の注意点

**ファイル名は URL に使える文字（半角英数字とハイフン・アンダースコア）にしてください。**

- スペースや日本語、`#` `?` `&` などを含むファイル名はリンクが正しく動作しない場合があります。
- 日本語タイトルの曲でも、ファイル名はローマ字などに変換することを推奨します。
  - 例: `曲名.zip` → `song-title.zip`

## サイズと容量の制限

配信ファイルは Git（GitHub）にコミットして Vercel から配信するため、両者の制限を受けます。

### GitHub（[公式ドキュメント](https://docs.github.com/en/repositories/working-with-files/managing-large-files/about-large-files-on-github)）

| 項目 | 制限 |
|---|---|
| 1ファイル 50 MiB 超 | 警告が出る（プッシュ自体は可能） |
| 1ファイル 100 MiB 超 | **ブロックされる**（通常の Git では追加不可） |
| ブラウザからのアップロード | 25 MiB まで |
| リポジトリ全体 | 1 GB 未満が理想、5 GB 未満を強く推奨 |

「ブラウザからのアップロード 25 MiB」は GitHub の Web 画面から直接ファイルを追加する場合の制限です。上記手順の `git push` による追加では該当しません。

### Vercel Hobby プラン（[公式ドキュメント](https://vercel.com/docs/limits)）

| 項目 | 制限 |
|---|---|
| 帯域（Fast Data Transfer） | 100 GB / 月 |
| 1デプロイあたりのファイル数 | 15,000 まで |
| 商用利用 | **不可**（商用は Pro プランが必要） |

### 運用の目安

- **1ファイルは 50 MiB 未満**に収めることを目安にしてください（GitHub の警告回避とリポジトリ肥大化防止のため）。
- これを超えるファイルや、多数・大容量を配布したい場合は、リポジトリに含めず**外部のファイル配布サービス等**に置き、`url` に外部URLを指定してください（例: `{ "url": "{{url_diff}}" }` で外部の配布ページURLを参照）。
